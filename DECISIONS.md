# Decisions

## Status: what is verified and what is not

Verified in this repo: typecheck, 176 unit tests, 25 Playwright flows (WebKit at iPhone 15 Pro size; the offline flow on Chromium), a production build with its service worker, and a Deno typecheck of every Edge Function.

**Not verified, because it needs accounts, devices or secrets that were not available:** the Supabase migrations and merge RPC against a real database; Notion OAuth and sync against real Notion; Stripe checkout and webhook; Web Push delivery; Sign in with Apple; the Shortcut (it must be built on an iPhone and signed by Apple, see `docs/SHORTCUT.md`); Lighthouse scores; install, haptics and swipe feel on a real iPhone in standalone mode. The code for each is written to the documented APIs but has never run against the live service. Treat the "done when" list as open until those are exercised.

## Product and tech

- **Local-first.** Dexie is the source of truth; Supabase holds a replica in one `records` table (one JSON document per record). Conflicts resolve last-write-wins **per field** using a `_f` clock map; ties break on `deviceId`. The same merge exists in TypeScript (`data/merge.ts`) and SQL (`merge_record`). Check ins, practice logs and journal entries use deterministic ids (`detId`) so two devices logging the same thing merge instead of duplicating.
- **No UI kit, no Tailwind.** CSS Modules over tokens ported unchanged from the design system, except that secondary label greys and the accent were darkened slightly to hold 4.5:1 contrast. Type sizes are rem-based with a `--type-scale`.
- **Icons:** Phosphor SVGs through a generated registry of regular, bold and fill weights only. The brief named `@phosphor-icons/react`; the React package ships six weights per icon and tripled the icon bundle, so this uses the same icons from `@phosphor-icons/core`.
- **Gestures** are hand-written with pointer events and WAAPI springs (`lib/motion.ts`), from the design system's motion helpers: edge-swipe back, sheets that follow the finger and dismiss downward, a scrubbing tab lens.
- **Content** is JSON per Onda, lazy-loaded, validated by Zod and precached by the service worker. Practice ids are stable because logs point at them.
- **Haptics:** `navigator.vibrate` where it exists; on iOS a programmatic toggle of `<input type="checkbox" switch>` (iOS 17.4+). Unverified on a device.
- **Face ID lock** uses WebAuthn with a platform authenticator: a privacy screen, not encryption.
- **Free tier** (not specified in the brief): three running Lagos, Stoicism only, no custom Ondas, no integrations. Constants are in `data/catalog.ts`.
- **Integrations require Ondas+ and a backend**, and their state comes from the server, never a local flag.
- **Calendar:** private per-user ICS feed with floating local times, a `webcal://` link, and a one-time `.ics` built on the device for offline or account-less use. Rotating the token revokes the old URL.
- **Reminders:** a Shortcut plus a JSON feed (GET today, POST completions back). Labelled "Via Shortcuts".
- **Notion:** one-way, app to Notion. Tokens are AES-GCM encrypted server-side. A trigger queues changed records with a 60 second debounce; a per-minute cron drains the queue under 3 requests per second with retry and backoff; failures stay queued and are reported on the connection. Pull from Notion is not implemented (stretch goal).
- **Gallery** is a plain catalogue of ready-made Lagos. The "Top Lagos" ranking and participant counts were removed in 1.2: they were seed numbers, not real usage, and a ranking implies data that does not exist.

## Ondas+ and the App Store

**Beta placeholder (1.2).** Until real payments are switched on, "Get Lifetime" in the app unlocks Ondas+ on the device and nothing is charged (`BETA_PAYMENTS` in `app/src/sync/entitlement.ts`). The paywall says so. A server that has no purchase on record never takes a beta unlock back. Building with `VITE_PAYMENTS=live` restores the real Stripe Checkout flow, which needs a signed-in account. Because the unlock is a local flag, it is not a security boundary: do not ship a public build without `VITE_PAYMENTS=live`.

Trial and purchase are an **app-level entitlement**: the server sets `trial_started_at` once per account (a reinstall cannot restart it) and Stripe's webhook is the only thing that sets `lifetime`. StoreKit is not available to PWAs. If Onda is ever wrapped natively and distributed through the App Store, Apple requires In-App Purchase to unlock digital features, so the Stripe path would have to be replaced by StoreKit (or removed) in that build, and Restore would need to read StoreKit entitlements. A PWA sold through Stripe from the web sits outside App Store review.

## Update 2.1

- **Performance (measured).** Lighthouse, Chromium, mobile emulation with simulated slow 4G and 4x CPU slowdown, production build. Before (one run): score 63, first contentful paint 3.8 s, largest contentful paint 4.9 s, total blocking time 420 ms, script boot-up 1.8 s, page weight 617 KiB. After (four runs): score 75 to 88, first contentful paint 2.4 s every run, largest contentful paint 3.4 to 3.8 s, total blocking time 80 to 400 ms, boot-up 0.4 to 0.9 s, page weight 387 KiB every run. Blocking time varies a lot between runs, so treat it as improved but not settled. These are worst-case-phone numbers, not iPhone numbers. A WebKit probe on the same build: first paint 6.9 s to 0.2 s on a cold load, JavaScript transferred 533 KB to 297 KB.
- **What changed.** zod no longer loads at start-up: schemas live in `data/schemas.ts` and load only for import, sync and custom Ondas; shipped content is trusted at runtime because `content:check` and a unit test prove each file equals its own parse (`npm run content:normalize` fixes a file). A tiny HTML shell paints at once. The first screen's chunk is fetched in parallel with the database. The Ondas are no longer all parsed at launch (the service worker already caches them) and the other screens warm one per idle slice. The edge shadow on a sliding page is a gradient strip instead of a 24px blur. The root uses 100svh.
- **Not done.** Initial JavaScript is about 190 KB gzipped, over the 170 KB target. The rest is React, i18next, TanStack Query, Dexie and the icon registry (about 50 KB gzipped); shrinking it means replacing i18next or splitting icon weights, which is a larger and riskier change. GitHub Pages cannot set Cache-Control headers, so sw.js and index.html rely on the service worker update flow. The frame-rate numbers from headless WebKit are not trustworthy and were not used.
- **Storage.** The app asks for persistent storage once onboarded and shows a message if a write fails because the device is full.
- **Content.** Every Onda has rewritten rules and five rewritten tasks in its own voice. Sources and cultural-care rules are unchanged in meaning.

## Update 5.1

- **Top bar on iPhone: what was actually wrong (still not verified on a device).** Three earlier attempts assumed iOS reads `theme-color` or the page background live. It does not. Since iOS 26, WebKit colours the bar behind the clock from an opaque fixed element a few pixels below the top edge of the page (`LocalFrameView::fixedContainerEdges`), samples it when the page loads, and for a viewport-sized fixed layer keeps the colour it already has. Our `body` is such a layer, so the bar kept whatever colour the page had at launch. Reports from real devices agree that only a fresh page load updates it: WebKit bugs 300965 and 301994 (the latter open again on iOS 27), and the write-ups in designloves/poppins#49, k2b-dev/cloud#542, coder/xum#5643, thcolin/sensorr#340 and cole-titze/nhl-odds#101.
- **The fix has two parts** (`src/app/statusBar.ts`). First, `#status-strip` in `index.html`: an opaque strip fixed to the top edge, above everything, at least 6px tall on iOS, painted in the page colour by the inline script before the first paint. That is the element iOS samples, and on installs where the page runs under the bar it is what shows behind the clock. Second, when the colour iOS sampled no longer matches the page, the app reloads itself and returns to the same tab and pushed pages (`sessionStorage` `onda.resume`). A switch between light and dark reloads after 350 ms. A smaller change, such as the wash of a newly started Onda, reloads when the app goes to the background. It never reloads while a sheet or menu is open, while text is being typed, during onboarding, while the page is navigating away, or within two minutes of opening a file picker, and at most once per target colour.
- **Do not ask people to remove the Home Screen icon.** Earlier notes and the 5.0 What's New text said to remove and re-add the app. On iOS that deletes the app's stored data. The text is gone, and none of the 5.1 fix depends on re-adding. Settings, Help and About now has a Top bar row (Browser, Drawn by iOS, Drawn by Onda) so a report can say which kind of install it is.
- **Sixty-four Ondas.** Zulu, Bantu, Khmer Empire and Celtic were added with their own themes, emblems and fonts (Lexend, Sora, Suwannaphum with Khmer numerals, Uncial Antiqua). Bantu is a language family and the Onda says so: it names the language of every word and proverb, and notes that the word is offensive in South Africa when applied to people.
- **Page title.** The floating title of a pushed page had no backing, so text ran through it once the page was scrolled. It now gets the same glass as the buttons beside it as soon as the page moves.
- **Full check.** Static audit of all 64 Ondas (icons, fonts, emblems, themes, times), 638 unit tests, 33 end-to-end tests and a sweep that opens every Onda page and guide in light and dark (`app/shots/sweep.mjs`). Opening and closing many Ondas leaves the number of mounted pages unchanged.

## Update 5.2

- **Practices and tasks are one list, new every day.** An Onda no longer shows a fixed list of practices and a second list of tasks. `planForDay(content, day)` in `app/src/data/derive/plan.ts` gives each day up to five: one for the morning, one for the afternoon, one for the evening, one small extra, and one about taking the world in (a book, a film, a song, a dish). It is computed from the content and the day number alone, so it is the same on every device and nothing new is stored. The practices of a slot take turns, and each returns in the next of its written variations (shown as "Today: ..."). The extra comes from the Onda's tasks. The immerse practice walks through the kinds one a day, using the Onda's own hand-written task for a kind first and then its Immerse list from the top.
- **Why not write five practices for each of thirty days by hand.** That would be 9,600 practices across 64 Ondas, none of which could be checked properly. The existing content already held about 5 practices with 3 variations each, 8 to 10 tasks and about 45 Immerse items per Onda. Rotating those gives 30 or more different things in two weeks (a unit test holds every Onda to that), and every one of them was written for that Onda.
- **Small pleasures.** Four light things per Onda were added (`content/sources/treats.cjs`, 256 in all): something to taste, hum, look at or make. They join the tasks as `treat-*` and so turn up as the day's small extra. For the Ondas about living peoples they stay with what a guest may do. `apply-treats.cjs` writes them into the JSON files and `build.cjs` does the same when it rebuilds an Onda from its source.
- **Ticks.** Every row of the day's list is logged in `practiceLogs`. A practice shown in a variation keeps its own id, so stats and "keep as a Lago" are unchanged. A task is logged under its task id, an immerse practice made from an item under `im-<item id>`. A run's snapshot now carries `perDay`, the number of practices in a day, and rates use it. Runs begun before 5.2 have no `perDay` and are counted as before. Ticks made on the old Tasks list (`taskLogs`) are kept in the database but no longer shown.
- **Links in Immerse: searches, not stored addresses.** None of the 2,799 Immerse items had an address, and I could not verify thousands of them. A wrong or dead link is worse than none. So `app/src/content/links.ts` builds a search on a fitting service from the item's own title and maker: Spotify, Apple Music and YouTube for music, YouTube and JustWatch for film, Open Library and Google Books for reading, Wikimedia Commons and Google Arts for art, a recipe search for food and drink, Maps for places, Wikipedia for customs, games and festivals, Forvo for how a word is said. They cannot point at the wrong page and they do not go stale. On a phone the Spotify, YouTube and Maps links open the app when it is installed. The sheet says that each button opens a search outside Onda.
- **Fact check: what was and was not covered.** I read every quote with its attribution, every book, film, recording and work of art with its maker and year, every person with their dates and every history timeline entry, for all 64 Ondas (about 3,000 items), against my own knowledge and not against the internet. I found no errors. Two blank date fields were filled, and Gnosticism (no listening at all) and Aztec (one film, one recording) were given more. Not covered in this pass: food, drink, customs, games, festivals, places, the word lists and the long guide texts. The Ondas about living peoples are still unreviewed by those communities.
- **Length in days.** Every place a length is chosen (an Onda's page, a new Onda, a new Lago, onboarding, the default in Settings) now uses `DayScroller`: a small row of numbers that slides sideways and settles with one in the middle. It takes the width it is given. It replaces the plus and minus stepper and the tall ruler. It is a `slider` to assistive technology and answers to the arrow keys.
- **Ondas+ is EUR 2,49 a month or EUR 24,99 once.** `plus` gained the value `monthly`. The paywall offers both plans and the trial is unchanged. Payments are still the beta placeholder unless `VITE_PAYMENTS=live`. For live payments the server side is written but not deployed or tested against Stripe: a migration (`20261009000000_monthly.sql`), `stripe-checkout` takes `plan` and uses `STRIPE_PRICE_MONTHLY` in subscription mode, and `stripe-webhook` sets `monthly` on a paid subscription and removes it when the subscription ends, never touching `lifetime`. Before going live: create the two prices in Stripe, set both price ids, and add the `customer.subscription.updated` and `customer.subscription.deleted` events to the webhook.
- **Loading screen.** Two faults. The light launch images had no `prefers-color-scheme` condition, so in dark mode both the light and the dark image matched and iOS could show the light one; they are now marked light only. And the page's own loading screen showed the word Onda in grey while the launch image shows three blue waves; it now shows the same waves at the same size, on the colour the app is about to use, and fades out. The launch image itself is chosen by iOS from the phone's setting before any code runs, so with the phone in light mode and Onda set to dark, the first instant is still light. That cannot be changed from a web app.
- **Look.** Each Onda's page opens on a hero in its own fill and pattern with its emblem as a large watermark, its origin under the name, and section headings in its own lettering, with emblem dividers between the parts. Immerse opens with today's pick, shows every kind on one screen as small tiles, and lists items as plain rows (number, title, maker, tick) instead of repeating the same picture on every card.

## Update 5.2.1

- **Immerse is back as it was in 5.1.** The 5.2 redesign (today's pick on top, small tiles, plain rows) was removed from the Immersion screen: the grid of kinds with pictures and the shelf of cover cards are as before. The Find it buttons in an item's sheet stay, because those were asked for separately.
- **The day's practices have a thread.** The first version of the plan rotated an Onda's practices by time of day, and an audit showed that most Ondas had only one or two practices for the morning, so the same name came back every day and only its variation changed. Now each time of day has an anchor (the Onda's first practice for that time, or its first task if it has none). The anchor comes back two days in three, each time in its next variation, so it feels like the same practice a little new each time. On every third day that slot shows something else from the tradition instead, working through everything the Onda has for that time before repeating. The three times of day change on different days. The fourth practice is a small extra, a different one every day, from all the Onda's non-Immerse tasks. The fifth is the Immerse practice, as before.
- **More to rotate through.** 178 new practices (`content/sources/dailies1.cjs`, `dailies2.cjs`) were written so that every Onda has at least five things for each of morning, afternoon and evening. Together with the existing practices, tasks and the four small pleasures, each Onda now shows at least fifteen different non-Immerse practices in its first two weeks (a unit test requires ten). New practices are plain tasks (`daily-*`) with a short note; they carry no how-to text, which only the original five practices of each Onda have.
- **Dark mode Full guide.** The text passed the contrast rules (worst case 5.8 to 1, most of it above 7), so the trouble was comfort, not a failing number: long paragraphs, sub-headings and the labels of the tabs you are not on were all the same mid grey. In dark mode they are now a lighter grey, long text has more line spacing, the links (Expand all, jump chips) are lighter, and the large faint letters behind each title are quieter. `app/shots/contrast.mjs` measures every text run in every guide tab for one appearance.
